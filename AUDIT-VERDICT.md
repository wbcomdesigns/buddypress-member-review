# Audit Verdict: buddypress-member-review

**Audit type:** Static-only self-audit (no browser tools used — per instruction, another agent owns the browser). Code inspected at branch `3.7.1` working tree, header/readme already bumped to `3.8.0`. Nothing in this plugin was edited or committed.

## Shippable? YES, WITH FIXES
The 3.8.0 security/cron/alert-toast fixes documented in the changelog are real and verified in code (ownership check, single cron registration, alert() removal all confirmed). No new blocker was introduced by the dark-mode CSS push. But there is one confirmed **functional regression for translated sites** (Approve Review action) and a genuine **accessibility regression** (focus outline removed with no replacement, admin + front) that should be fixed before the next tag.

## Sellable? WITH POLISH
Core review/moderation/rating flow is solid and the security hardening this cycle was done correctly. The stale docs (CLAUDE.md, package.json, .pot version) and one dead settings-tab file bundled in the free zip are the kind of loose ends that read poorly in a paid-product audit even though they don't break anything today.

## Verified-clean (worth recording so it isn't re-audited)
- `bupr_update_review` ownership/capability gate (`includes/bupr-ajax.php:710-728`) is genuinely hardened — mirrors the sibling `bupr_edit_review` check (`post_author` match OR `edit_others_posts`). Confirmed by reading the code, not just the changelog.
- `bupr_add_owner_reply` and `bupr_flag_review` both have correct nonce + ownership/login checks for their respective operations.
- The two admin-post handlers (`bupr_handle_dismiss_flag`, `bupr_handle_resolve_flag`, `admin/bupr-admin.php:743-815`) use per-action nonces (`bupr_dismiss_flag_{id}` / `bupr_resolve_flag_{id}`) plus `current_user_can( 'edit_post', $review_id )` — correctly capability-scoped per review, better than a blanket `manage_options`.
- Native `alert()` calls are fully removed from `assets/js/bupr-front.js` (replaced with the toast/confirm system in `admin.js`) — the 3.7.1-era CLAUDE.md open-finding is stale, not current.
- Cron `bupr_cron_recalculate_user_reviews_batch` is registered exactly once (`daily`, guarded by `wp_next_scheduled`) — the activation-time double-registration is gone.
- Front-end reviews tab (`includes/templates/bupr-reviews-tab-template.php:21-36`) uses `WP_Query` with `posts_per_page`/`paged` (not `-1`), satisfying the pagination checklist item for the primary review list.
- The `wppqa_scan_plugin` "dead-handler: bupr_approve_review registered but never called from JS" finding is a **false positive** of the scanner (it only scanned `assets/js/`, not `admin/assets/js/`) — the handler is wired at `admin/assets/js/bupr-admin.js:280-303`; see Finding #1 for the real bug in that same handler.
- Enum consistency, REST↔JS contract, and template-contract checks all passed clean (plugin has 0 REST routes by design, documented in `audit/manifest.json`).
