# Security review - BuddyPress Member Reviews 3.8.1

Scope: full diff v3.8.0..3.8.1 plus every AJAX / admin-post handler in the plugin (no REST routes). Method: code read of each handler, then a direct POST per handler as the wrong role with a valid page nonce, on wbcom-free.local (WP 7.1, BuddyPress 14.4, Reign 8.0.7 / BuddyX 5.1.8 / BuddyX Pro 5.1.8).

## Findings fixed in this release

| Severity | Where | Attacker story | Fix |
|---|---|---|---|
| High | `includes/bupr-ajax.php` `bupr_approve_review` | A Contributor or Author opens any wp-admin posts screen, reads the localized admin nonce and publishes any pending review, including their own, skipping moderation. | Requires `edit_others_posts`; Approve link only shown to those users; `nopriv` registration removed. |
| High | `includes/bupr-ajax.php` `bupr_update_review` | The author of a pending or report-hidden review edits it and the handler forces `post_status=publish`, putting it back in public without moderation. | Edits keep the current status. |
| High | `includes/templates/bupr-single-review-template.php` | Anyone (logged out included) reads pending and report-hidden reviews at `/reviews/view/<id>/`; IDs are sequential, so they can be enumerated. | Non-published reviews visible only to their author and moderators; a review only renders under the reviewed member's profile. |
| Medium | Same template | Anonymous review single view printed the reviewer's login in the avatar `alt` and their user ID in its class. | Anonymous reviews print neither. |
| Medium | `includes/bupr-ajax.php` submit handler | Reviewer / Reviewee Roles only hid the Add Review button; any logged-in member could POST a review. | `bupr_roles_allow_review()` enforced server-side. |
| Medium | `bupr_edit_review`, `bupr_update_review` | Update Review OFF only hid the Edit button; members could still edit. | Both refuse with `update_disabled` unless `edit_others_posts`. |
| Medium | `admin/bupr-admin.php` dismiss / resolve | Checked `edit_post` on the review, so an Author-role reviewer could dismiss reports against their own review. | Requires `edit_others_posts`. |
| Low | `includes/bupr-shortcodes.php` | Top members list printed login usernames (half of each member's credentials). | Display names. |
| Low | `includes/bupr-ajax.php` | Review submit action registered for logged-out visitors (handler refused them immediately). | `nopriv` registration removed. |

## G1 mechanical sweep

`security-sweep.sh --baseline v3.8.0`: CRITICAL 2 -> 0; `esc-sql-on-nonscalar` removed (the update handler no longer passes `esc_sql()` on the ID).

## Scanner-visible but safe

| Pattern | Location | Why it is safe |
|---|---|---|
| `check_ajax_referer` (nonce-only-auth heuristic) | `bupr_approve_review` | Followed by `current_user_can( 'edit_others_posts' )`. |
| `extract( $args, EXTR_SKIP )` | `includes/bupr-general-functions.php:82` | Template loader; `$args` is built by the plugin, never from the request; `EXTR_SKIP` cannot overwrite existing variables. Same pattern as WooCommerce `wc_get_template()`. |
| No `ABSPATH` guard | `uninstall.php` | Guarded by `WP_UNINSTALL_PLUGIN`, the correct check for that file. |
| No `ABSPATH` guard | `languages/*.l10n.php` | Generated WordPress translation files that only `return` an array; no side effects. |

## Authorisation matrix (G2, AJAX + admin-post; no REST routes)

| Action | Logged out | Subscriber (other member) | Author of the review | Contributor | Editor / Admin |
|---|---|---|---|---|---|
| Submit review | refused (`0`) | allowed if roles allow; refused otherwise | n/a | as subscriber | allowed |
| Edit / update review | refused | refused (not owner) | allowed unless Update Review off; status kept | refused | allowed |
| Owner reply | refused | refused (not reviewed member) | refused | refused | allowed (`manage_options`) |
| Report review | refused | allowed once | refused (own review) | allowed once | allowed |
| Approve review | refused | refused | refused | refused (verified) | allowed |
| Dismiss / resolve reports | refused | refused | refused (verified with an Author) | refused (verified) | allowed |

All "verified" cells were dispatched in the browser walk with a nonce valid for that user (see `docs/qa/.last-smoke-pass.json`, rows D1, D2, R1-R4, R10, R11).
